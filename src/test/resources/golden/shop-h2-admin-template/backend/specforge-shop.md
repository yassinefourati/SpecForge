# Module "shop": finishing the integration

Generated by SpecForge (admin-template@1) from "Shop". SpecForge wrote new files only:

- `backend/src/main/java/com/admintemplate/shop/`: `Country`, `Customer`, `Order`, `Product`, `Tag`
  (entity, repository, DTOs, service and controller each)
- `backend/src/main/resources/db/migration/V12__shop.sql`: the tables (prefix `shop_`), the permission and the menu entries
- `backend/src/test/java/com/admintemplate/shop/ShopModuleIT.java`: CRUD on every table
- `frontend/apps/web/src/features/shop/`: per table a list page, a create / edit dialog, API hooks and
  types; the routes under `frontend/apps/web/src/app/(app)/shop/` (`/shop/countries`).
  Many-to-many ids and binary values are kept as they are in the dialog and changed through the API.
  The pages are not in the menu yet: set "Menu section" (e.g. sales) to add entries, or open the routes directly.

The project keeps a few registries in hand-written files. SpecForge never edits them; add these lines yourself.

## 1. Permission (required: the application refuses to start without it)

`backend/src/main/java/com/admintemplate/security/Permissions.java`, with the other constants:

```java
    /** Create, change and delete shop data (SpecForge module). */
    public static final String SHOP_MANAGE = "shop.manage";
```

and at the end of `ALL`:

```java
            SETTINGS_ADMIN, AUDIT_VIEW, SHOP_MANAGE);
```

and in `Authorize.java` (`PermissionsTest` checks that every permission has one):

```java
    public static final String SHOP_MANAGE = HAS + Permissions.SHOP_MANAGE + END;
```

and in `frontend/apps/web/src/lib/auth/permissions.ts`, at the end of the `Permission` type:

```ts
  | 'shop.manage'
```

The generated controllers use the same expression as a literal, `"hasAuthority('shop.manage')"`, so they
compile before these lines exist.

## 4. Audit log

`backend/src/main/java/com/admintemplate/audit/AuditedEntities.java`: every entity is either recorded or listed as
left out (`AuditMappingIT` checks it). To leave the module's entities out, add to `NOT_AUDITED`:

```java
            "com.admintemplate.shop.Country",
            "com.admintemplate.shop.Customer",
            "com.admintemplate.shop.Order",
            "com.admintemplate.shop.Product",
            "com.admintemplate.shop.Tag",
```

To record them instead, add an `AuditEntity` value and a `type(...)` entry per entity, as for `Customer`.

## 5. Tests that pin the project's lists

- `backend/src/test/java/com/admintemplate/reference/FormConstraintsTest.java`, `reportsEveryForm`: add
  `"shopCountry"`, `"shopCustomer"`, `"shopOrder"`, `"shopProduct"`, `"shopTag"` at the end of its `containsExactly(...)`.
- The new permission is listed last (highest position), so in the tests that pin the permissions:
  - `security/PermissionControllerIT`: add `"shop.manage"` at the end of `ALL`, and `"SALES"` at
    the end of the areas in `listsRolesPermissionsByPositionAndGrants`;
  - `user/MeControllerIT`, `permissionsFollowTheRoles`: add `"shop.manage"` after `"audit.view"`;
  - `navigation/MenuControllerIT`, `listsEveryRowWithItsLabelAndTheChoicesOfTheEditor`: one more permission in
    `$.permissions.length()`.

Then `./mvnw verify` (backend) runs the project's tests and `ShopModuleIT` (CRUD on every table of the
module), and `pnpm lint`, `pnpm type-check` and `pnpm test` (frontend) check the pages.

- Use-case controllers are not generated for admin-template modules yet; their tables get their own endpoints.
